# Гибридный поиск: hybrid-v1

Исторический шаг hybrid-v1, реализован и проверен 2026-11-27. Эксперимент на ранее оплаченном кэше;
не полный векторный индекс и не независимая оценка качества.
Текущая политика hybrid-v2/.45 и полный корпус — [vector-corpus.md](vector-corpus.md).
Параметры .35 и результаты ниже относятся к первоначальному v1; CLI исполняет текущую версию.

## Конвейер и границы

1. Общий `search.Prepare` сохраняет query-v4 и явные ограничения.
2. BM25 получает до 20 семейств. ExactOnly/LimitReason отключают векторную ветку:
   артикул или неразобранное число нельзя заменить ближайшим вектором.
3. Кэшированный корпус embedding-text-v1 и запрос читаются через общий Runtime,
   Live=false, без Provider. Cosine использует первые 512 из 1536 компонент;
   это локальное сокращение, а не новая платная модель.
4. До 50 групп с cosine >= 0.35 становятся кандидатами. Порог — начальный
   ограничитель эксперимента, не доказанная граница релевантности. Метки целей
   и scope запроса не участвуют в поиске. Holdout не читается.
5. Elasticsearch подбирает SKU кандидатов по паре vendor-path + group_id,
   применяя те же строгие фильтры до collapse. Один запрос на список кандидатов,
   без N отдельных поисков. Проверяются fingerprint, catalog ID и версии;
   переключение alias не смешивает снимки.
6. Списки объединяются по FamilyID: сумма 1/(60 + rank), rank с единицы.
   Повторы внутри одного списка дают один голос. Равенство — FamilyID по возрастанию.
   SKU берётся из BM25 при наличии семейства в обоих списках. Максимум 20 кандидатов
   каждой ветки, затем пользовательский limit. Фильтры выбранного SKU проверяются
   повторно общим application/lexical.Search перед выдачей.
7. Положительная цена имеет общий приоритет: неоплаченные варианты BM25 отбрасываются,
   если векторная ветка нашла подходящие SKU с ценой. Без цены ищем только при
   отсутствии подходящих SKU с ценой в обеих ветках. Ноль не бесплатный товар.

Без кэша запроса/корпуса либо при ошибке векторного адаптера возвращается BM25
с явным trace о fallback; отмена context не превращается в успешный ответ.
Нельзя добавлять четыре произвольных товара: Describe сохраняет shortfall,
provisional семейства не подтверждают выполнение требования четырёх семейств.
Близость не является проверкой совместимости и не создаёт допродажу.

## Приёмочные проверки

- Domain: общий победитель RRF, повторы без дополнительного голоса, стабильное
  равенство, конфликт идентификаторов и нечисловые оценки отклоняются.
- Application: семантический кандидат, priced-first между ветками, общий collapse,
  ExactOnly, cache/error fallback, отмена и запрет смешивания снимков.
- Реальный Elasticsearch: группа с несколькими SKU/редакциями, неверная версия,
  роль, неизвестные ёмкости и другой vendor-path не проходят до collapse;
  stale fingerprint отклоняется; используются только собственные тестовые индексы.
- Development replay: 60 tuning + 16 ранее замороженных probes, расходы до/после
  неизменны. Отдельно считать известную группу в top4 и отсутствие подходящего SKU;
  не объявлять эти метрики независимым измерением или четырьмя проверенными товарами.

## Оставшаяся работа

Полный корпус, сверка SHA feed, разрешение на новый исходящий корпус и индексация
описаны отдельным шагом в [vector-corpus.md](vector-corpus.md).
Имеющаяся оценка $0.08975356 — верхняя граница исходной подготовки текста, а не
фактический расход новой индексации. HTTP, разбор LLM, verifier допродаж отдельно.

## Запуск и фактическая проверка

После подготовки/оплаченного пилота, при наличии PostgreSQL и активного lexical-v5:

```powershell
go build -o bin/search.exe ./cmd/search
./bin/search.exe -query "хочу находить уязвимости в сети компании" -hybrid-corpus artifacts/embedding-pilot-dataset.json
python scripts/evaluate-tuning.py --hybrid-corpus artifacts/embedding-pilot-dataset.json --output artifacts/hybrid-tuning.json
python scripts/evaluate-tuning.py --probes --hybrid-corpus artifacts/embedding-pilot-dataset.json --output artifacts/hybrid-probes.json
python scripts/evaluate-tuning.py --probes --output artifacts/lexical-probes.json
```

Ключ не используется; live-флага в этом режиме нет. Без кэша нового запроса
возвращается BM25 и Hybrid.VectorStatus=fallback. Не требуется, чтобы текст
присутствовал в разметке: используется текстовый ключ кэша, цели не читаются
ранжированием. Получение эмбеддингов новых текстов будет отдельным live-подключением.

Корпус SHA `b9512910badb491301de61174b37d40987b389563636be487fca00292a0ea828`:
512 групп, cosine-prefix-512, окно 50, два списка до 20, RRF k=60, порог 0.35.
Эти параметры зафиксированы перед данным прогоном; по результатам не менялись.

| Набор | Текущий BM25/query-v4 | Гибрид с проверкой SKU |
| --- | --- | --- |
| Tuning: известная группа в top4 | прежний прогон 52/52 | 52/52 |
| Tuning: бренд / отрицательные | прежний прогон 6/6 и 2/2 | 6/6 и 2/2 |
| Замороженные development probes | 0/16 | 13/16 |

На tuning: 54 used, 5 no_candidates, 1 skipped_exact. Ошибок исполнения 0.
Оставшиеся промахи probes: 05 (управление проектами), 06 (корпоративная почта),
14 (российская ОС). Они не исправлялись заменой эталона или отключением фильтров.
Raw BM25 7/16 из пилота использовал другой, изолированный индекс/OR-запрос:
его нельзя смешивать с текущим production baseline 0/16 на этих формулировках.

Проверены unit domain/application, cache-only адаптер, реальные PostgreSQL/ES,
vet и сборка. До реализации domain/application зафиксированы красные прогоны.
Цена/ledger после replay: 19 прежних резервирований, usage 1 193 120 nanodollars
(0.00119312 USD), unresolved 0; в кэше прежние 586 векторов. Новых API-вызовов нет.
Development-отчёты находятся в игнорируемом artifacts; holdout не запускался.

Это известные положительные группы, а не полная разметка всех результатов.
13/16 не доказывает релевантность остальных трёх карточек, четыре разных
подтверждённых семейства, пригодность каждой лицензии или качество полного каталога.
Порог cosine пока не калиброван для открытых запросов; режим включается явно.
