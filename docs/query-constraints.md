# Условия запроса: query-v3 / characteristics-v4 / lexical-v4

## Приёмка расширения ёмкости

DevicesLimit, IPAddressesLimit и ParticipantsLimit — независимые верхние границы
ёмкости. Явные «на N ПК», «на N IP», «до N участников» берутся из названия SKU
с evidence; число пользователей/узлов их не заменяет. Диапазоны, отрицания,
смешанные единицы и неизвестные значения не доказывают ёмкость.
Запрос требует известную границу >= N; фильтры применяются до collapse и
повторно проверяются application во всех поисковых попытках.

Deployment дополнительно понимает «серверная лицензия», «на одном сервере» и
«на одном рабочем месте». Office Home 2024 сопоставляется с канонической
редакцией home_student только по названию Microsoft Office и версии 2024:
[Microsoft: formerly Home & Student](https://www.microsoft.com/en-us/microsoft-365/p/office-home-2024/CFQ7TTC0PQVJ).
Это правило названия редакции, не перенос характеристик из product group.

Приёмка: четыре ранее отклонённых tuning-сценария, unit-тесты границ/единиц,
реальный Elasticsearch, новый полный снимок/индекс. Holdout не запускать.

## Критерии

Разобрать явные редакции, срок (месяцы/годы/бессрочно), число пользователей,
назначение server/workstation и наличие. Различать пользователей, устройства,
участников и IP-адреса: неизвестная ёмкость другого типа не заменяет нужную.
Запросы/цели holdout не используются для настройки правил.

Распознанный фрагмент переносится из поискового текста в строгий фильтр с
сохранением исходного запроса и списка условий. Конфликт текста с CLI-фильтром,
два разных срока/редакции и неоднозначный диапазон возвращают invalid query.
Если условие распознано, но не поддержано индексом (например, срок в днях),
возвращается явный shortfall, без выдачи неподтверждённых точных совпадений.
Нераспознанный текст не удаляется ради повышения метрики.

## Каталог

- TermKind/TermMonths — только из «Срок действия»/«Срок лицензии» с evidence.
  «Срок техподдержки» не становится сроком лицензии; даты/диапазоны/пустые маркеры
  остаются unknown. Разные явные сроки дают conflict.
- Edition — из «Редакция»/«Версия», ограниченных явных фраз редакции в названии,
  а также названий лицензий AnyDesk и Microsoft Office. Не из product group.
- UsersLimit допускает явное «на N пользователей» в названии того же SKU,
  с сохранением conflict при противоречии параметру. ПК/узлы/IP не считаются users.
- Deployment — явные фразы назначения в названии, включая «серверная лицензия».
  Упоминание ОС/сервера в описании не доказывает лицензионное назначение.
- Новые атрибуты сохраняются через domain.Normalize в новом immutable снимке.
  Неизвестные/конфликтные значения не удовлетворяют строгому фильтру.

Новая политика characteristics-v4 и схема lexical-v4 требуют повторного импорта
и индексации. Старые данные/индексы не переписываются и не удаляются.
Чтение устаревшей схемы возвращает not ready, а не ложное отсутствие товара.

## Проверки

Сначала unit-тесты нормализации SKU и разбора запросов; затем фильтры до collapse,
повторная application-проверка, реальный ES и полный feed. Проверять отрицательные
числа, разные единицы, нулевые значения, конфликты CLI/текста и смешанные сроки.
Публичный HTTP API пока не реализован; этот шаг меняет внутренние DTO и CLI.

## Разметка

Пользователь подтвердил принятие всех 100 кейсов в чате 2026-11-27. Статус
accepted_by_user фиксируется вместе с автором/датой и цепочкой хэшей; запросы,
цели и ограничения не меняются. Это принятие пользователем, не сертификат вендора.
Holdout остаётся неиспользованным для настройки. Принятие разметки и измерение
качества — разные действия; полноценная Precision/nDCG не следует из brand scopes.
