# Поиск брендов и названий: план исправления

## Диагностика 2026-11-28

Cache-only HTTP API, действующий снимок characteristics-v5 / lexical-v7 / query-v9.
Шесть development-регрессий: Adobe, адоб, адоь, Photoshop, фотошоп, фотошор.
Top1: 2/6. Только английские контрольные названия дают искомый бренд/продукт.
Полный локальный ответ: artifacts/named-search-baseline.json (игнорируется Git).
Повтор: `python scripts/diagnose-named-search.py` против cache-only API 8080.
Скрипт сам не вызывает OpenAI, но сервер должен работать без live-флагов.
Оценка проверяет собственное имя продукта и vendor-path, а не упоминание
в описании/плагинах. Это узкая регрессия, не независимая оценка и не вся полнота поиска.

Причины по коду: нет русских алиасов Adobe/Photoshop; транслитерация даёт
adob/fotoshop; fuzzy допускает чужие похожие названия. Порядок priced exact →
priced expanded → unpriced exact допускает вытеснение точного недоступного
продукта приблизительным платным совпадением. Совпадение не доказывает намерение.

## Последовательность реализации

1. Диагностика и регрессии: текущий документ, fixture и HTTP-runner.
2. Распознавание: snapshot-bound словарь брендов/продуктов из каталога;
   отдельно версионированные синонимы. Fuzzy по словарю, а не отдельное правило
   для каждой опечатки. Оценка конкурирующих кандидатов, отказ от автоматической
   подмены при неоднозначности. Бренд, продукт и задача — разные типы намерения.
3. Поиск: исходный запрос и строгие условия сохраняются; уверенная идентичность
   ограничивает кандидатов. Цена/наличие ранжируют внутри подходящей области,
   а не дают чужому приблизительному товару преимущество над искомым продуктом.
   available_only всегда строгий; версии/артикулы не исправляются fuzzy.
4. API/UI: подтверждённая интерпретация с возможностью исходного поиска;
   альтернативы отдельно, фактическая недоступность без обещания заказа.
5. Оценка: другие бренды, новые ошибки первой буквы/пропуска/перестановки,
   неоднозначности и отрицательные контроли, версии/артикулы/фильтры.
   Top1, релевантность top4, ложные исправления и задержка. Новый независимый
   набор фиксируется до просмотра выдачи; старый holdout не становится новым.

## Границы

Новые продукты обновляют словарь вместе со снимком, без обучения модели и ручного
перечисления ошибок. Изменение словаря входит в identity и инвалидирует кэш
интерпретаций. Provisional family не скрывает совпадение продукта и не доказывает
четыре семейства. Базовый поиск работает локально без платных моделей.
Нельзя устранять ошибку только boost Adobe, ID эталона или добавлением двух алиасов.
Принятие: шесть регрессий проходят, новые опечатки проверены отдельно, строгие
условия не ослаблены, общий development-прогон и независимая оценка разделены.
Следующие этапы ещё не реализованы; допродажи отложены до проверки базового поиска.

## Распознавание catalog-names-v1

Созданы domain NameDictionary, application names.Load, PostgreSQL LoadNames и
диагностическая команда `go run ./cmd/name-resolve -query "фотошоп"`.
Источник читает vendors и собственные имена групп из закреплённого снимка,
только с доверенным store.softline.ru URL. Категории без предложений не становятся
продуктами; группа не объявляется подтверждённым семейством.
Синоним применяется лишь при наличии канонического имени в словаре.
Полное содержимое, snapshot ID и NamePolicyVersion входят в SHA-256.

Полные имена сравниваются с ограничением 1 правка для 4–5 букв и 2 для 6+;
поддержаны перестановка и ошибка первой буквы. Транслитерация — вторичная гипотеза.
Равные/близкие конкуренты дают ambiguous с кандидатами, не автоматическую подмену.
Цифры/пунктуация, длинные задачи и запросы короче четырёх букв не исправляются.
Кандидаты ограничены пятью; оценки — внутренние расстояния, не вероятность.

Это диагностический компонент: ещё не подключён к HTTP/CLI search, фильтрам ES,
коррекциям интерфейса и коммерческому ранжированию. Загрузка полного feed через
PostgreSQL reader оказалась медленной на локальном диске; реальный полный smoke
не завершён, время запуска не заявляется приемлемым. Перед подключением требуется
компактная материализация словаря, повторное использование в памяти и измерение.
Unit-тесты синтетические; PostgreSQL-тест использует изолированную схему.

## Подключение компактного словаря

Предыдущий PostgreSQL reader оставлен диагностическим. Рабочий маршрут:

```powershell
python scripts/prepare-name-catalog.py --feed C:/Users/hypoc/Downloads/Mindbox.yml.gz.xml
go run ./cmd/api -name-catalog artifacts/name-catalog.json
# Сохранить hybrid для задач; распознанные названия ищутся локально:
go run ./cmd/api -name-catalog artifacts/name-catalog.json -vector-corpus artifacts/vector-corpus.json -parser-mode replay
go run ./cmd/search -name-catalog artifacts/name-catalog.json -query "фотошор"
```

Файл генерируется из feed без разметки запросов; содержит vendor, собственное имя
группы, vendor-path и group IDs. Источник сверяется с active PostgreSQL snapshot
и normalization version. Размер ограничен 4 МиБ; загрузка однократная в память.
Полный feed: 5 642 записи, 676 652 байта. SHA содержимого входит в fingerprint
словаря; смена feed требует новой генерации и перезапуска. Горячего обновления нет.
Это локальный доверенный build artifact, не подписанный внешний справочник.

Server-owned SearchBackend распознаёт подготовленный запрос, сохраняя исходный
ввод и строгие условия. Уверенный продукт ограничивает GroupID и vendor-path,
бренд — vendor-path и Vendor до collapse, во всех ценовых попытках. Возврат
повторно проверяется по SKU ProductName/Vendor, scope и catalog ID. При переключении
индекса на другой снимок возвращается not ready; словарь нужно пересобрать.
Цена имеет приоритет только внутри распознанной области. Неуверенные и запросы
по задаче сохраняют прежний backend; общий legacy-порядок для них не изменён.
Распознанные названия не требуют vector/parser API. available_only и версии
не ослабляются. Идемпотентный replay намеренно сохраняет ранее записанный ответ.

HTTP smoke: исходные шесть запросов дают ожидаемый top1 (6/6 вместо 2/6).
Дополнительно bdobe, phtoshop, фтошоп исправлены, FQC-10572 сохраняет Windows.
Десять replay совпадают с исходными ответами. В малом прогоне HTTP 76–287 мс,
один запуск оптимизированного CLI 159 мс; это не нагрузочная оценка p95.
Tuning 52/52 + 6/6 + 2/2, development 8/16 без изменения; holdout не запускался.
Реальный ES-тест: недоступный точный продукт выше чужого priced совпадения;
плагин и чужой vendor с тем же group ID не проходят; availability/version строги.

Остаётся: corrections/уточнение неоднозначности в API/UI, расширенная оценка
на других брендах и новый независимый набор. Полные имена с цифрами пока не
распознаются этим словарём и идут прежним защищённым маршрутом. Четыре релевантных
семейства для каждого запроса не гарантированы; для Photoshop найден один продукт.

## Обратная связь об интерпретации

Уверенное распознавание сохраняется в Result и постоянном replay вместе с SHA
словаря. API заполняет существующий corrections: original — распознанная часть
запроса, replacement — каноническое имя; kind — synonym для алиаса, typo для
правок, transliteration для чистой транслитерации. Одно изменение регистра не
считается исправлением. Это эвристика, не вероятность и не подтверждение лицензии.

При ambiguous нельзя выдавать произвольно выбранный товар: ES используется только
для получения версии/метаданных, hits удаляются, платные ветки не вызываются.
В clarification передаются названия кандидатов с просьбой уточнить продукт и
производителя. Frontend показывает corrections и clarification даже без shortfall.
История ввода, фильтры и защита от устаревших ответов сохраняются. Контракт ответа
не расширяется; выбор кандидата можно отправить обычным новым поиском.
Отдельный режим поиска без интерпретации ещё не реализован.

Политика catalog-names-v2 дополнительно объединяет одинаковые канонические
имена бренда/продукта в одном vendor-path (AnyDesk), предпочитая продукт при
равной дистанции. Разные названия и разные вендоры не объединяются.
Vendor-path становится алиасом бренда только при совпадении с отдельным словом
его собственного имени (Corel Corporation → corel). Продуктовый путь владельца
не подтверждает имя бренда: /astralinux/ не заменяет запрос ОС на «Группа Астра».
Обратная транслитерация вычисляется при загрузке словаря.

Fuzzy сохраняет границы слов. Для коротких слов (одна из сторон <=5 букв)
первая буква должна совпадать; для длинных имён ошибка первой буквы допустима.
Это сознательное ограничение против ложных paint → SAINT и point → Joint.
Прежний дополнительный smoke bdobe больше не обещает исправление новым словарём.
Нераспознанные запросы всё ещё используют legacy-поиск, качество всех его
приблизительных совпадений этим изменением не исправлено.

Расширенный development smoke: 20 запросов и 20 идентичных replay; исходные
шесть регрессий сохранены. corle даёт уточнение Corel Corporation / Qlik Core,
пустой matches, total_matches=null и shortfall_reason=null. Paint/point не получают
ложных corrections. Tuning после проверки product-path остался 52/52 + 6/6 + 2/2,
development 8/16. Это не независимый набор и не полная оценка релевантности top4.
DOM-тесты проверяют текст интерпретации, сохранение ввода и состояние уточнения;
визуальная/browser QA не проведена. Компактный отчёт — testdata/evaluation/name-feedback-v1.json.
