# Поиск брендов и названий: план исправления

## Диагностика 2026-11-28

Cache-only HTTP API, действующий снимок characteristics-v5 / lexical-v7 / query-v9.
Шесть development-регрессий: Adobe, адоб, адоь, Photoshop, фотошоп, фотошор.
Top1: 2/6. Только английские контрольные названия дают искомый бренд/продукт.
Полный локальный ответ: artifacts/named-search-baseline.json (игнорируется Git).
Повтор: `python scripts/diagnose-named-search.py` против cache-only API 8080.
Скрипт сам не вызывает OpenAI, но сервер должен работать без live-флагов.
Оценка проверяет собственное имя продукта и vendor-path, а не упоминание
в описании/плагинах. Это узкая регрессия, не независимая оценка и не вся полнота поиска.

Причины по коду: нет русских алиасов Adobe/Photoshop; транслитерация даёт
adob/fotoshop; fuzzy допускает чужие похожие названия. Порядок priced exact →
priced expanded → unpriced exact допускает вытеснение точного недоступного
продукта приблизительным платным совпадением. Совпадение не доказывает намерение.

## Последовательность реализации

1. Диагностика и регрессии: текущий документ, fixture и HTTP-runner.
2. Распознавание: snapshot-bound словарь брендов/продуктов из каталога;
   отдельно версионированные синонимы. Fuzzy по словарю, а не отдельное правило
   для каждой опечатки. Оценка конкурирующих кандидатов, отказ от автоматической
   подмены при неоднозначности. Бренд, продукт и задача — разные типы намерения.
3. Поиск: исходный запрос и строгие условия сохраняются; уверенная идентичность
   ограничивает кандидатов. Цена/наличие ранжируют внутри подходящей области,
   а не дают чужому приблизительному товару преимущество над искомым продуктом.
   available_only всегда строгий; версии/артикулы не исправляются fuzzy.
4. API/UI: подтверждённая интерпретация с возможностью исходного поиска;
   альтернативы отдельно, фактическая недоступность без обещания заказа.
5. Оценка: другие бренды, новые ошибки первой буквы/пропуска/перестановки,
   неоднозначности и отрицательные контроли, версии/артикулы/фильтры.
   Top1, релевантность top4, ложные исправления и задержка. Новый независимый
   набор фиксируется до просмотра выдачи; старый holdout не становится новым.

## Границы

Новые продукты обновляют словарь вместе со снимком, без обучения модели и ручного
перечисления ошибок. Изменение словаря входит в identity и инвалидирует кэш
интерпретаций. Provisional family не скрывает совпадение продукта и не доказывает
четыре семейства. Базовый поиск работает локально без платных моделей.
Нельзя устранять ошибку только boost Adobe, ID эталона или добавлением двух алиасов.
Принятие: шесть регрессий проходят, новые опечатки проверены отдельно, строгие
условия не ослаблены, общий development-прогон и независимая оценка разделены.
Следующие этапы ещё не реализованы; допродажи отложены до проверки базового поиска.

## Распознавание catalog-names-v1

Созданы domain NameDictionary, application names.Load, PostgreSQL LoadNames и
диагностическая команда `go run ./cmd/name-resolve -query "фотошоп"`.
Источник читает vendors и собственные имена групп из закреплённого снимка,
только с доверенным store.softline.ru URL. Категории без предложений не становятся
продуктами; группа не объявляется подтверждённым семейством.
Синоним применяется лишь при наличии канонического имени в словаре.
Полное содержимое, snapshot ID и NamePolicyVersion входят в SHA-256.

Полные имена сравниваются с ограничением 1 правка для 4–5 букв и 2 для 6+;
поддержаны перестановка и ошибка первой буквы. Транслитерация — вторичная гипотеза.
Равные/близкие конкуренты дают ambiguous с кандидатами, не автоматическую подмену.
Цифры/пунктуация, длинные задачи и запросы короче четырёх букв не исправляются.
Кандидаты ограничены пятью; оценки — внутренние расстояния, не вероятность.

Это диагностический компонент: ещё не подключён к HTTP/CLI search, фильтрам ES,
коррекциям интерфейса и коммерческому ранжированию. Загрузка полного feed через
PostgreSQL reader оказалась медленной на локальном диске; реальный полный smoke
не завершён, время запуска не заявляется приемлемым. Перед подключением требуется
компактная материализация словаря, повторное использование в памяти и измерение.
Unit-тесты синтетические; PostgreSQL-тест использует изолированную схему.
