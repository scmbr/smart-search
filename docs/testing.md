# План тестирования и оценки

Матрица ниже содержит выполненные и будущие сценарии; наличие строки не означает
успешного прогона. Reader/CLI, PostgreSQL-снимки, нормализация и лексический
baseline уже имеют исполняемые тесты. HTTP-сервер, гибридный поиск, рекомендации
и frontend ещё не реализованы.

- `internal/catalog`, `cmd/catalog-check`: XML/gzip, цены, лимиты, диагностика,
  отмена, ошибки sink и CLI.
- `internal/domain/catalog`, `internal/application/catalogimport`,
  `internal/infrastructure/postgres`: нормализация/снимки, повтор, checkpoint,
  транзакции, смена active, ошибки и блокировка writer.
- `internal/domain/search`, `internal/application/lexical`: семейства, запросы,
  документы, индексация и повторная проверка ограничений SKU на границе адаптера.
- `internal/infrastructure/elastic`: HTTP DSL, сбои и реальные индекс/alias,
  ранжирование, collapse разных групп одного семейства, запасная выдача.
- `contracts`: OpenAPI/fixtures и происхождение примеров. Это не тест работающего
  HTTP-сервера. Проверка статуса набора запрещает называть раскрытые примеры holdout.
- `scripts/test_family_audit.py`: независимое от поиска извлечение фактов plain/gzip.

Обычный запуск: `go test ./...`, `go vet ./...`, `go build ./...`,
`python -m unittest discover -s scripts -p 'test_*.py'`. Без переменных
TEST_POSTGRES_DSN/TEST_ELASTICSEARCH_URL реальные интеграции пропускаются;
в CI они запускаются с сервисами и обязательны через quality-gate. OpenAI не нужен.

Актуальные границы разметки, воспроизводимые команды и очередь независимой
проверки — [evaluation-review.md](evaluation-review.md). Исходные 10 запросов
и бывший holdout используются только для разработки/regression. Активный набор — 60 tuning + 40 holdout, разнесённых по брендам;
первые 8 holdout-кейсов расширены до 40 до просмотра выдачи,
разметка всех 100 кейсов принята пользователем 2026-11-27; оценка на holdout не запускалась.

## Уровни

- Go testing: нормализация, ограничения, RRF, группировка, события и валидация.
- Go httptest: контракт HTTP и ошибки с подменой внешних клиентов.
- Интеграционные: реальные PostgreSQL/Elasticsearch с малыми fixtures, без OpenAI.
- Vitest: логика UI и защита от устаревших ответов.
- Playwright: поиск, карточки, подсказки, аналитика и режим разбора.
- Отдельный live/evaluation набор: OpenAI только при явном запуске и лимите расходов.

## Данные оценки

Начальный набор — 10 строк из предоставленной таблицы. Цели содержат страницы
продуктов и категории, поэтому сравнение по одному URL предложения недостаточно.
До оценки сопоставить цели с группами/категориями feed и проверить их доступность.
Начальное сопоставление 10 целей с группами, vendor/category и примерами SKU
сохранено в source-queries.json. Оно не доказывает пригодность любого SKU группы:
сохраняются ограничения платформы, версии и роли предложения.

Добавить опечатки, сленг, смешанные языки, запросы по задаче, ограничения лицензий,
неоднозначные и неизвестные запросы. Отделить набор настройки от независимой
оценки; варианты одной исходной формулировки не распределять случайно между ними.
Ожидаемые цели фиксировать до просмотра результатов на независимом наборе.

Baseline — заранее описанный простой лексический поиск. Это наша воспроизводимая
точка сравнения, а не измерение действующего поиска Softline.
Дополнительно сравнить BM25 без векторов, векторы и гибридный вариант на одном наборе.

Основные метрики по D-018: Family Hit@4, Precision@4 и nDCG@4 при наличии разметки,
число разных семейств в top4 и доля программно проверенных допродаж. Hit@1/MRR
остаются диагностическими. Для категории/vendor-page в исходном Excel перед оценкой
размечаем допустимые семейства; попадание в произвольную широкую категорию недостаточно.
Также измеряем долю без релевантных совпадений, нарушения ограничений,
покрытие обязательных характеристик, p50/p95 и стоимость. Всегда указывать число
примеров; по десяти запросам не делать вывод о качестве всего каталога.

## Производительность и готовность

Фиксировать характеристики компьютера, версии, размер индекса, concurrency,
холодный/прогретый кэш, доступность API и отдельно подсказки/поиск/индексацию.
Численные пороги утверждаются после пилота и до финальной приёмки.
gofmt/go test/go vet/go build применяются ко всем Go-пакетам. Unit-тесты domain и
application проверяют активацию, повторение, отмену, ошибки и checkpoint.
TEST_POSTGRES_DSN включает реальные интеграционные тесты транзакций, миграций,
блокировки writer и сохранения active при ошибках; в CI они обязательны.
Frontend-проверки появятся вместе с интерфейсом.

Актуализация 2026-11-28: независимое сравнение полного hybrid завершено;
исторические формулировки «не запускался» выше относятся к прежнему состоянию.
Результат и ограничения: [independent-evaluation.md](independent-evaluation.md).
