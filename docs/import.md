# Потоковое чтение и проверка каталога

Статус: reader/валидатор и CLI реализованы и проверены. Связь: T-01–T-03, N-02, R-01.
Этот документ описывает reader без БД. Его подключение к PostgreSQL и активация
снимка описаны в [контракте сохранения](persistence.md); поискового индекса пока нет.

## Контракт пакета catalog

`Read(ctx, reader, sink, options) (Report, error)` определяет plain XML/gzip по
сигнатуре и разбирает YML последовательно. Sink получает категории и подходящие
предложения по мере чтения. nil sink означает проверку без сохранения.
Read не закрывает переданный reader; его жизненным циклом управляет вызывающий код.

Категории могут ссылаться на родителей, определённых далее в разделе categories.
Весь раздел categories должен предшествовать offers. Проверяются единственные
корень yml_catalog, shop, categories и offers. Произвольный XML с тегами offer
в других местах не принимается за каталог. Внешняя DTD не загружается и внешние
сущности не раскрываются; нормальная декларация shops.dtd допускается как данные.

Цена разбирается десятично в int64 копеек без float. Пустая/нулевая цена неизвестна,
а исходное значение сохраняется. Отрицательная, дробь точнее копейки, неверный
формат и переполнение отклоняются. RUR/RUB нормализуются в RUB; остальные валюты
пока отклоняются явно. Флаг available обязан быть true или false.

Сохраняются source ID, group ID, исходные атрибуты, URL, vendor, артикул, название,
описание, параметры (включая повторы и единицы измерения). Для известных маркеров
«не определено»/«другое или отсутствует» сохраняется RawValue, но Known=false.
Роль лицензии, версия и семейство на этом шаге не угадываются по группе.

## Ошибки и отчёт

- Ошибка XML/gzip, структуры, лимита, context или sink возвращается как error,
  прекращает чтение; Complete=false, CanActivate=false.
- Некорректная запись получает Issue с code/entity ID, не передаётся sink;
  чтение продолжается. Отчёт содержит seen/accepted/rejected.
- Дубликаты категорий/предложений, неизвестные родители и циклы категорий
  диагностируются. Повторный ID отслеживается даже для ранее отклонённой записи.
- Конфликт group_id атрибута/элемента и дубликаты скалярных полей не исправляются
  выбором последнего значения. Повторяющийся param допустим.
- CanActivate=true только при полном чтении, хотя бы одном принятом предложении
  и отсутствии диагностик. Это признак валидности, не команда активации.

Sink пишет только во временную область будущего снимка: поздняя ошибка может
инвалидировать ранее переданные записи. Reader не гарантирует транзакцию и не
объявляет ранние callback результатами активного каталога. Ошибка sink оборачивается
с сохранением errors.Is и останавливает обработку.

По умолчанию лимит записи/одного внешнего XML-токена — 1 MiB, распакованного
документа — 1 GiB. Список подробных диагностик ограничен 100; общие счётчики
не обрезаются. Лимиты настраиваются. Память зависит от категорий, множества
увиденных ID, лимита текущей записи и количества сохранённых диагностик;
полные предложения reader не накапливает.

## CLI

Команда `go run ./cmd/catalog-check -file PATH` читает файл либо stdin
при `-file -`, пишет JSON-отчёт в stdout и ошибку выполнения в stderr.
Коды выхода: 0 — валидный снимок, 2 — завершён с диагностикой данных,
1 — ошибка выполнения/неполное чтение. Доступны max-record-bytes,
max-document-bytes, max-issues. Отмена прерывает обработку.

Это dry-run без изменения каталога, сети и API-расходов. Метрики времени и памяти
описывают конкретный прогон; конечная heap_alloc не называется пиком памяти.

## Проверка предоставленного feed

На Windows/Go 1.27.3 полный прогон снимка 2026-11-25 прочитал 291 988 701 байт,
9 311 категорий и 136 040 предложений; accepted=136040, rejected=0, issue_count=0.
Один итоговый прогон занял 14,196 секунды. Это время reader/валидатора без БД,
sink-записи и индекса. Отчёт сохраняется локально в игнорируемом artifacts/catalog-check.json.
Параметры лицензий сохранены, но их семантика и рекомендации этим прогоном не проверены.
