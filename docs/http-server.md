# Первый HTTP-сервер: состояние процесса и готовность

Первый шаг этапа 4 реализует существующий контракт `/api/v1/health/live` и
`/api/v1/health/ready`. Остальные операции OpenAPI остаются планом реализации;
сервер не выдаёт mock-поиск за реальный API.

- live: HTTP 200 `{"status":"ok"}`, без БД/ES/OpenAI.
- ready: HTTP 200 только при наличии ready PostgreSQL-снимка с текущей
  нормализацией и единственного ready ES-индекса с корректным fingerprint,
  совместимыми версиями документа/нормализации и тем же catalog ID.
- После проверки ES повторно читать active PostgreSQL-снимок; его смена во
  время проверки означает 503, не смешанную готовность.
- Ошибки обязательных сервисов/несогласованность: 503 по схеме Error,
  безопасный `service_unavailable`, без DSN/ключей/необработанных ошибок.
- Deadline readiness 5 секунд, отмена запроса передаётся портам. OpenAI и
  векторный кэш не участвуют: лексический режим достаточен для ready.
- JSON-ошибки для неизвестных путей и неподдержанных методов; health без кэша.
- По умолчанию слушать `127.0.0.1:8080`; этот шаг предназначен для локального
  стенда. ReadHeader/Read/Write/Idle timeout, предел заголовков, graceful shutdown.
- Сервер не применяет миграции и не меняет каталог/alias; подготовка прежними CLI.

Команда: `go run ./cmd/api`; опция `-listen 127.0.0.1:8081` меняет локальный порт.
Для старта требуется настроенный PostgreSQL; если первоначальное соединение
не удалось, процесс завершается безопасной ошибкой. После старта сбои видны
через ready, а live остаётся доступным.

SDD: сначала unit-тесты domain согласованности снимков, application отказов/
отмены/смены active, затем HTTP/контрактные тесты и real-adapter проверки.
Факт готовности относится к моменту проверки, это не распределённая транзакция
между PG/ES и не доказательство качества поиска/совместимости рекомендаций.

## Фактическая проверка

Unit domain/application/HTTP, контрактные тесты реальных handler-ответов,
проверка ES failed shards и real PostgreSQL (собственная тестовая схема) прошли.
Отдельный собранный `bin/api.exe` проверен с текущими PG/ES: live=200/ready=200;
с недоступным ES: live=200/ready=503, без внутренних адресов/секретов в ответе.
Запущенные smoke-процессы остановлены. Локальный отчёт:
artifacts/http-health-smoke.json. Graceful shutdown проверен отдельным Go-тестом;
smoke-процессы после проверки завершены через дескрипторы собственных процессов.
Сервер не оставлен работающим в фоне, его запускают приведённой выше командой.
