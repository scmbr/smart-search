# Полные эмбеддинги для поиска по задачам

## Причина и решение

Кэш уже хранит text-embedding-3-small размерности 1536, но hybrid-v3 сравнивал
первые 512 компонент. Development-аудит всего корпуса обнаружил потерю ранга:
probe-16: целевая группа 12 → 3, probe-09: 67 → 25 при использовании 1536.
Это ранги кандидатов, ещё не доказательство попадания пригодного SKU в выдачу.

Hybrid-v4 использует все сохранённые компоненты в обоих vectorcache-адаптерах.
Порог 0.45, окно 50, RRF, приоритет ProductName и SKU-фильтры не меняются.
Trace VectorDimensions=1536 означает настроенную размерность, включая режим,
где поиск векторов пропущен. Фактическое использование показывает VectorStatus.
Модель/текст/кэш-ключи/корпус/индекс прежние: повторного получения эмбеддингов нет.

## Проверки

- Красный тест до реализации: prefix не различает совпадающие первые 512
  компонент при противоположном сигнале после них; полный cosine отвергает
  неверный документ. Без Provider и API-платежей.
- Существующие тесты слабых соседей, целостности корпуса, загрузки один раз,
  cache miss, price priority, фильтров и отмены остаются обязательными.
- Воспроизвести 60 tuning + 16 development probes; отдельно target@1/@4,
  fallback и время batch. Старый holdout не запускать для выбора решения.
- Оценить память: векторы документов требуют около 147 MiB для 12 538 × 1536
  float64 вместо 49 MiB для prefix-512, без учёта строк, map, runtime и GC.
  Число компонент cosine вырастает втрое; измерять скорость, не обещать ускорение.

Независимые измерения предыдущего frozen hybrid-v2 остаются историческими,
новый backend не должен проходить старый freeze. Для новой независимой оценки
нужен новый заранее закреплённый набор, до просмотра результатов.

## Другие причины development-промахов

Корпус часто содержит лицензионные атрибуты вместо описания функциональности.
Полная размерность не добавляет отсутствующие факты и не подтверждает назначение.
Шесть ранее отсутствовавших кандидатов частично остаются ниже 0.45; не снижать
порог ради известной цели. Probe-03 имеет известный барьер лицензий перехода.
Для probe-02 в каталоге есть priced новые лицензии: отсутствие в top4 нельзя
объяснять полным отсутствием товара. Probe-16 имеет три priced SKU целевых групп.
Полная SKU eligibility/допродажи остаются задачей verifier.

## Измеренный результат

Development probes: group hit@4 7/16 → 8/16, group hit@1 4/16 → 6/16.
Новый hit probe-16 (rank3); probe-11/12 поднялись с rank2 на rank1.
Ни один прежний hit не потерян. Probe-09 теперь имеет кандидата в окне,
но не target в top4 — это не объявляется исправленным сценарием.
Tuning: group@1/@4 52/52, brand 6/6, negatives 2/2 без регрессий.
Ошибок исполнения/fallback 0; новые API-вызовы не требовались.

Один batch 16 probes: 15 336 → 16 508 мс; tuning 60: 13 910 → 13 596 мс.
Это разные прогоны на локальном стенде с загрузкой CLI/корпуса, а не
контролируемый latency benchmark или p95. Ускорение не заявляется.
Сводка, SHA отчётов и полный аудит рангов:
[full-vector-development-v1.json](../testdata/evaluation/full-vector-development-v1.json).
Качество полного набора четырёх товаров и независимый выигрыш не доказаны.
