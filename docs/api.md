# Контракт API

Машиночитаемый источник истины — [OpenAPI 3.0.3](openapi.yaml). Базовый путь /api/v1.
Сервер `cmd/api` реализует только `/health/live` и `/health/ready`;
остальные операции ниже — контракт следующих шагов. [Примеры](../testdata/api/cases.json) содержат
успех с четырьмя продуктами, пустую выдачу, ограниченный режим и ошибки; они синтетические.

| Операция | Назначение |
| --- | --- |
| POST /search | Выполнить поиск по запросу, фильтрам и контексту сессии. |
| GET /suggest | Получить подсказки; не регистрирует отправленный поиск. |
| GET /products/{id} | Получить продукт и варианты предложений активного снимка. |
| POST /events | Принять click/recommendation_click и другие разрешённые события. |
| GET /analytics/summary | Получить агрегаты за интервал. |
| GET /analytics/queries | Получить частые и проблемные запросы с основаниями классификации. |
| GET /searches/{id}/trace | Получить фактические этапы обработки для режима демо. |
| GET /health/live | Проверить, что процесс работает. |
| GET /health/ready | Проверить готовность обязательных компонентов. |

## Поиск

Запрос содержит query, session_id, category/segment context, разрешённые фильтры
и параметры страницы. Явные ограничения отделены от интерпретации модели.
Неизвестные поля и некорректные значения валидируются; длина запроса ограничивается.
Предел query — 256 Unicode-символов, пустые/пробельные запросы запрещены. limit от 4
до 20, по умолчанию 4; размер JSON-тела до 16 KiB. Превышение размера — HTTP 413.
availability_policy по умолчанию priced_first; available_only — строгий вариант
без запасной выдачи недоступных предложений. Если подходящих предложений с ценой нет,
priced_first допускает неизвестную цену и устанавливает unpriced_fallback_used=true.
Роль предложения отличает новую лицензию от
продления, обновления и поддержки; неизвестная роль не выдаётся за подтверждённую.

Idempotency-Key обязателен для POST /search, уникален в рамках сессии и хранится
минимум 24 часа. Повтор того же ключа/тела возвращает тот же поиск без нового события.
Изменение тела при том же ключе — 409 idempotency_conflict. Порядок ключей JSON
не считается изменением тела; сравнивается каноническое содержимое.
Курсор связан с query, context, filters, limit и версией индекса; пагинация не
считается новым поиском. Новая страница использует новый Idempotency-Key,
но сохраняет исходный search_id.
Срок курсора — 24 часа; потеря нужного снимка — 409 snapshot_expired. Неверный
или изменённый курсор — 400 invalid_request. Порядок устойчив, равные оценки
разрешаются стабильным product ID. Реализацию хранения/подписания определим позже.

Ответ содержит search_id, исходный запрос, исправления, использованный контекст,
версию каталога/индекса, группы результатов, сведения об ограниченном режиме,
предложения уточнения и длительность. У карточек стабильные product/offer IDs.
Пагинация требует стабильного порядка для одного контекста и версии индекса.
Версия контракта — 0.2.0. family_id — отдельный стабильный идентификатор семейства.
top4 задаёт порядок первой четвёрки ссылками {section, product_id, family_id} на
карточки секций ответа. Семейства не повторяются между этими четырьмя позициями.
При двух совпадениях и двух проверенных допродажах все четыре входят в top4.
Для недобора обязательна shortfall_reason; это не считается выполнением требования
четырёх семейств. На оценке эталон сопоставляется с family_id через маппинг групп,
а не с выбранным offer_id. Для пагинации оценивается первая страница.
Контекст synthetic содержит явные origin=synthetic и profile_id; он не означает
синтетическое происхождение самих событий взаимодействия с демо.
Цена передаётся как status=known и целые amount_minor в копейках, currency=RUB;
входное RUR нормализуется в RUB. Неизвестная цена — status=unknown, amount_minor=null.
Ноль не является известной ценой. URL товаров и доказательств допускают только HTTPS.
Допродажа требует verification с passed, выбранной парой SKU и непустым набором
программных проверок характеристик/лицензий. Все обязательные checks должны пройти;
failed/unknown не допускаются в положительном отчёте. Источник без проверки
не является достаточным основанием рекомендации.

Ноль результатов — успешный ответ с пустыми совпадениями и объяснением.
Недоступность обязательного поискового сервиса — временная ошибка, не пустая выдача.
Недоступность OpenAI — успешный лексический ответ с явным degraded state.
Отсутствие эмбеддингов или исчерпание бюджета также явно обозначаются. Готовность
OpenAI не обязательна для /health/ready, если доступен лексический поиск.
Валидационные ошибки имеют стабильный машинный код и безопасное сообщение.

## События и доступ

Событие содержит event_id, search_id, session_id, тип, время и при необходимости
product/offer ID, позицию и источник клика. Backend валидирует связь с выдачей.
Для suggestion_selected используется suggestion_id, а не обязательный search_id:
выбор подсказки происходит до отправки поиска. Клиент не отправляет search_submitted
и не может задавать origin=synthetic для произвольных событий.
Повторная доставка event_id идемпотентна. Время получения хранится отдельно
от клиентского времени. Не разрешаем frontend произвольно задавать бизнес-метрики.
Повтор идентификатора с другим содержимым — 409; неизвестный search/card/suggestion
или несовпадение сессии — 400. Согласованность section и type проверяется backend:
recommendation_clicked относится только к recommendations.

Аналитика принимает обязательные from/to в RFC3339 и использует полуинтервал
[from,to) по времени исходного поиска. from должен быть раньше to. origin=demo
по умолчанию; synthetic выбирается явно только при чтении. Клики связываются
с поисками этой когорты по моменту получения до as_of. Это наблюдаемая доля кликов,
не атрибуция заказа. При searches=0 доли равны null, не 0. Технические сбои считаются
отдельно от успешных поисков и пустых совпадений.

Аналитика и trace предназначены для локального демо. Публичное размещение требует
отдельного решения об аутентификации и доступе; режим localhost не заменяет это решение.
Секреты и необработанные ошибки SDK в ответы не включаются.

Запуск и точные критерии готовности: [http-server.md](http-server.md).
