# Поиск и рекомендации

Связанные требования: R-01–R-08, R-11–R-12, N-03–N-06.

## Вход и контекст

Исходный запрос сохраняется неизменным. Контекст включает выбранную категорию,
явный демонстрационный сегмент и историю текущей сессии. По умолчанию профиль
не задан. История — сигнал, а не основание нарушать явно указанные ограничения.

Нормализация строит дополнительные варианты, не уничтожая исходный запрос.
Артикулы, номера версий, количество пользователей и сроки сохраняются.
Аббревиатура «мтс» неоднозначна: цель из контрольного набора не становится
универсальной заменой без контекста. Исправления отражаются в ответе.

## Поисковый конвейер

1. Выделить точные идентификаторы и обязательные ограничения.
2. Добавить проверенные синонимы, варианты написания и допустимые исправления.
3. Для сложной формулировки при необходимости запросить структурированную
   интерпретацию модели; не принимать её предположения за явные фильтры пользователя.
4. Получить BM25-кандидатов с приоритетом названия/артикула/категории над описанием.
5. Для смыслового запроса получить вектор и векторных кандидатов.
6. Объединить списки RRF по стабильным идентификаторам и проверить ограничения.
7. Сгруппировать предложения и выбрать подходящий вариант каждой карточки.
8. Применить доступность и подтверждённые бизнес-сигналы среди релевантных вариантов.
9. Добавить рекомендации и объяснения на основании фактических сигналов.

Лимиты кандидатов, параметры RRF, пороги релевантности и необходимость дополнительного
reranker определяются на наборе настройки. Независимый набор оценки не используется
для подбора этих параметров. Бизнес-буст не перекрывает несовместимость лицензии.

## Выдача

Результаты разделены на основные совпадения, альтернативы и сопутствующие решения.
Для карточки доступны product ID, выбранный offer ID, название, категория, ссылка,
изображение, известная цена, флаг доступности снимка, условия лицензии и причины выбора.
Неизвестные условия обозначаются неизвестными; цена 0 не показывается как «бесплатно».

Рабочая трактовка R-05: минимум четыре разные продуктовые карточки, если каталог
содержит обоснованные варианты. При нехватке явно сообщаем число совпадений,
отделяем дополнительные рекомендации, предлагаем уточнение/расширение запроса.
Не считаем четыре лицензии одного продукта четырьмя разными продуктами.
Правило требует уточнения у организаторов; не скрываем этот конфликт.

Пустой ответ означает отсутствие достаточных совпадений, а не доказанное отсутствие
товара в магазине. Отличаем отсутствующий продукт от отсутствия подходящей лицензии
и временной ошибки сервиса. При неоднозначности предлагаем варианты уточнения.

## Подсказки

Локальный поиск по словарю названий, категориям и синонимам. Генеративная модель
не вызывается на каждую букву. На frontend — debounce, отмена/игнорирование
устаревших запросов и управление клавиатурой. Значение задержки измеряется позже.
Запрос подсказки не считается отправленным поиском.

## Доказательства рекомендаций

Смысловая близость не является подтверждением совместимости. Рекомендация имеет
тип связи, объяснение, источник, дату проверки и ограничения версий/платформ.
Проверенные источники готовятся заранее; контент не исполняется как инструкции.
LLM не может вводить неизвестные товарные ID, изменять цены или обещать поддержку.
Если источник недоступен/не подходит к версии, утверждение совместимости не показывается.
Сравнение цен конкурентов и «часто покупают вместе» не заявляются без соответствующих данных.

Примеры источников для последующей проверки конкретных версий:
- [Кибер Бэкап и Astra Linux](https://cyberprotect.ru/podderzhivaemyie-texnologii/cyber-backup-astra-linux-specialedition/)
- [Совместимое ПО Astra](https://astra.ru/ready-for-astra/compatible-software/)

## Разбор запроса

Отдельное представление показывает исходный/нормализованный запрос, применённый
контекст, кандидатов каждого способа, фактические причины выбора, длительности
и ограниченный режим. Не раскрывает секреты и внутренние рассуждения модели;
объяснения описывают наблюдаемые этапы и проверенные основания.
