# Аналитика поиска

Связанные требования: R-09, R-10, R-12, N-03.
По уточнению экспертов №10 отдельный модуль необязателен и даёт бонус.
Мы сохраняем его в плане как выбранную функцию; логирование поддерживает проверку поиска.
Синтетический профиль контекста и синтетическое происхождение событий — разные признаки:
реальное взаимодействие с демо при synthetic-профиле остаётся origin=demo для события.

## События

- search_submitted: один выполненный поиск с search_id, контекстом, версией индекса,
  числом совпадений, режимом, исправлениями и длительностями.
- product_clicked: переход из результата с product/offer ID и позицией.
- recommendation_clicked: переход из рекомендаций с типом связи.
- suggestion_selected: выбор подсказки; сам по себе не отправленный поиск.
- session activity: данные для временного окна сессии, если оно реализовано.

Используем event_id для идемпотентности. Понятие сессии, тайм-аут и окно атрибуции
должны быть согласованы до метрик уходов/заказов. События разных сессий не смешиваются.
По контракту API выбор подсказки содержит suggestion_id и не требует search_id.
Отправку поиска регистрирует backend. Пагинация и идемпотентный повтор нового
search_submitted не создают. Попытка записать другое событие под тем же ID — конфликт.

Интервал аналитики [from,to) задан по времени исходного поиска. Клики учитываются
в той же когорте по известным связям и времени получения до as_of. Уходы и заказы
не вычисляются без отдельной политики сессий/атрибуции; доли при нулевом знаменателе
возвращаются как null. Технические ошибки вынесены в отдельный счётчик.

## Показатели

| Показатель | Определение |
| --- | --- |
| Число поисков | Количество уникальных search_id отправленного поиска. |
| Доля без совпадений | Поиски с нулём основных совпадений / все успешные поиски. Рекомендации не маскируют ноль. |
| Доля поисков с кликом | Поиски хотя бы с одним связанным кликом по товару / поиски в согласованной когорте. |
| Клики по рекомендациям | Отдельно от основных результатов; знаменатель — поиски с показанными рекомендациями. |
| Технические сбои | Отдельная доля ошибок; не смешивается с отсутствием совпадений. |
| Исправления | Частота реально применённых нормализаций/синонимов/исправлений. |
| Задержка и API | p50/p95, ошибки, токены, расходы и cache hit rate. |

Пустая выдача и нерелевантная выдача — разные случаи. Отсутствие клика не доказывает
нерелевантность. Оценка релевантности требует разметки или явного сигнала пользователя.

## Бизнес-выводы

Показываем частые запросы, проблемные формулировки и гипотезы: отсутствующий синоним,
неполное описание, неподходящая лицензия, отсутствие доступного предложения,
возможный пробел каталога. Каждая гипотеза связана с исходными событиями и
объяснением, может быть отклонена сотрудником; каталог автоматически не меняется.

Не заявляем измеренный рост заказов, маржу, конверсию и уходы без соответствующих
данных и согласованной атрибуции. Предоставленные экспертом сведения о mock-данных
учитываем явно: синтетические события отделены от взаимодействий с демо.
Исторические показатели из условия задачи — мотивация, не результат нашего эксперимента.
