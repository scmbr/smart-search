# Кэш и исполнение эмбеддингов

Следующий шаг после [пилота](embedding-pilot.md), до полной индексации/RRF.
Общий сервис используется live-режимом CLI и пригоден для будущего поиска.
Новых платных измерений в этой задаче нет; модель/ключ/разрешение не меняются.

## Инварианты

- Ключ кэша прежний: версия текста, модель, размерность и SHA текста. TTL нет:
  изменение текста/версии создаёт новый ключ. Повреждённый вектор — ошибка.
- До сети: повторная проверка кэша под блокировкой, резерв в общем ledger $5
  и постоянная связь cache key → reservation. Успех сохраняет usage и векторы
  атомарно, удаляя связь. Неопределённый исход блокирует повторную оплату ключа
  после рестарта. Автоматического истечения такой блокировки нет.
- PostgreSQL transaction advisory locks предотвращают одинаковые промахи
  между процессами. Два общих слота ограничивают API-вызовы в одной БД.
  Захват неблокирующий; ожидание ограничено 2 с, отменяется context.
  Слоты/ключи освобождаются rollback, в том числе при разрыве соединения.
- Batch <=32; проверка всего входа до сети. В одном вызове сервиса batches
  последовательные; параллельные callers разделяют два слота. Блокировки
  не держат строки ledger: для работы достаточно текущего pool MaxConns=3.
- Максимум три попытки только для явного HTTP 429 rate_limit_exceeded /
  rate_limit_error. Quota/auth/прочие 4xx, 5xx, тайм-ауты, повреждённый ответ
  не повторяются автоматически. SDK retries=0. Каждая попытка имеет новый
  резерв и входит в суммарный run cap $0.05. Для отклонённого HTTP-запроса
  верхний резерв консервативно сохраняется; бесплатность не предполагается.
  Поле api_reservations.outcome отличает rejected от unresolved/settled;
  Budget.UncertainNano включает все удержанные резервы без фактического usage.
- Backoff 250/500 мс + jitter <=100 мс; Retry-After (seconds/date) имеет
  приоритет, максимум допустимого ожидания 5 с. Больший срок возвращает
  ошибку вместо раннего повтора. Ожидания и API timeout 30 с отменяемы.
- Ошибки наружу без сырого ответа/ключей. Cache miss при выключенном live,
  исчерпание бюджета, busy и uncertain — явные ошибки. Будущий поиск должен
  перейти к BM25; подключение этого fallback — следующий этап поиска.

Классификация 429 quota/rate limit сверена с
[официальным описанием ошибок](https://developers.openai.com/api/docs/guides/error-codes).
Это намеренно консервативная политика повторов проекта.

## Приёмка

Unit: cache-only без провайдера, дедупликация/порядок, три rate-limit попытки,
бюджет до каждой попытки, отмена ожидания, отсутствие повторов quota/unknown,
проверка usage/векторов. Интеграция PostgreSQL: два независимых callers/хранилища,
общие слоты, повторная проверка кэша, pending после нового экземпляра,
освобождение guard при ошибке и отсутствие взаимной блокировки pool=3.
HTTP-моки проверяют классификацию и Retry-After, без реального OpenAI.
Replay существующего корпуса: 586 cache hits, 0 API-вызовов, прежние ранги/ledger.
Миграции 001/002 неизменяемы; новая 003 добавляет pending-связи.

Неразрешённый исход требует сверки с провайдером перед новой оплатой.
Не удалять pending/резервы и не сбрасывать ledger ради повторного запуска.
В текущем layout Runtime находится в application/embeddingpilot вместе с портами
пилота; внешний SDK и PostgreSQL остаются в infrastructure. HTTP API пока нет.

## Фактическая проверка 2026-11-27

Unit/HTTP-моки и реальные PostgreSQL/Elasticsearch тесты прошли. При одновременном
промахе второй caller наблюдал занятую блокировку, затем прочитал сохранённый
вектор; mock provider вызван один раз. Проверены общий лимит двух слотов,
pending при новом экземпляре хранилища, quota/unknown без повторов, успешный
повтор rate limit, отмена backoff и отдельный резерв перед каждой попыткой.

Локальный CLI replay после миграции 003: 512 документов / 76 запросов,
586 cache hits, 0 cache misses / API calls / нового usage. Rows, включая ранги
и scores, совпали с предыдущим replay; BudgetBefore/After совпали с прежним
ledger (actual 1 193 120 nanodollars, удержанных резервов 0).
Артефакт artifacts/embedding-runtime-replay.json остаётся локальным.

Go vet/build, форматирование, Python unittest и неизменность таблицы 100 кейсов
проверяются перед публикацией. Holdout и полная платная индексация не запускались.
