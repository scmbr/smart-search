# Именованные продукты и задачи: query-v4

## Приёмка

Разобрать оставшиеся промахи tuning без ослабления условий SKU. Holdout и разметку
100 кейсов не менять. Сначала unit-тесты domain/application, затем реальный ES
и полный снимок/индекс. Отсутствие подтверждения оставляет пустой ответ.

При явном названии продукта знакомое описание его назначения можно заменить
строгими family_id + product_type=software. Сохранять исходный запрос, фрагмент,
rule ID и источник в ProductIntents. Это ограниченный справочник назначения,
не проверка совместимости конкретной редакции/лицензии.

| Якорь | Поддержанная задача | Основание |
| --- | --- | --- |
| Astra Linux | операционная система / операционка | [Документация Astra](https://docs.astralinux.ru/latest/szi/szi/) |
| AnyDesk | удалёнка / удалённый доступ | [Функции AnyDesk](https://anydesk.com/en/features) |
| Кибер Бэкап | резервное копирование | [Документация Кибер Бэкап](https://docs.cyberprotect.ru/ru-RU/CyberBackup/17.0/user/backup-options.html) |
| Сканер-ВС | проверка/поиск уязвимостей | [Эшелон](https://npo-echelon.ru/scaner-vs-ins/) |

Источники просмотрены 2026-11-27; сеть в runtime не нужна. Без якоря не выбирать
бренд по задаче. Непонятные слова не удалять. Отрицания задачи — unsupported;
конфликты семейства/типа продукта — invalid query. Числа/артикулы не преобразовывать.
Срок, ёмкость, назначение server/workstation, роль и наличие сохранять во всех
попытках. family_id и FamilyConfirmed проверять до collapse и повторно application.

Контекстные языковые правила: фонетические small/security при Kaspersky;
EPP/ЕПП только в контексте MaxPatrol (в том числе ограниченная гипотеза опечатки
длинного слова). Home Business без and — редакция Office, а не отдельный продукт.
Не заводить таблицу полных tuning-запросов и отдельных опечаток.

## Исправление данных SKU: characteristics-v5 / lexical-v5

ESD — способ поставки, а не альтернативная роль полной лицензии. Сохранять
DeliveryMethod=esd отдельно, с raw evidence. Full + ESD означает известный Full;
ESD сам по себе не доказывает новую лицензию. Full + Renewal и неизвестный тип
по-прежнему не разрешают положительное заключение о роли.

Microsoft 365 Personal/Персональный и Family/для семьи извлекать как редакцию
только из явного названия того же SKU. 365 не становится технической версией.
Новая семантика требует immutable снимка и индекса; старые данные сохраняются.

Критические отрицательные тесты: чужое/неподтверждённое семейство, отрицания,
дополнительная неподтверждённая задача, конфликт CLI и текста, неизвестная ёмкость,
неподходящая роль, неподдержанная версия и неизменность числовых токенов.

Изменены внутренние DTO и CLI (`-family`); HTTP API ещё не реализован.
ProductIntents — объяснение языкового правила, не результат SKU-verifier.
Распознавание не полное: неизвестный текст сохраняется, запросы без якоря
не маршрутизируются в заранее выбранный бренд. Дальше — семантический поиск
и выборочный разбор сложных запросов, без заявления полной поддержки естественного языка.
